# Windows 启动与语音提问

可以直接使用已部署的 HTTPS 网站，也可以在本机启动完整项目。两种方式都支持浏览器本地识别，不需要 API Key；只有启动本机服务时才需要 Python。

## 直接使用网站

用正常的 Edge、Chrome 或 Firefox 打开项目网站，点击说话，按提示加载模型并允许麦克风。首次读取中文模型约44 MB、英文约41 MB，识别程序约5.8 MB。看到收音状态后再提问。这条路径不需要安装 Python 或 Vosk，提问音频在浏览器中处理。

加载完成后可以复用模型继续提问。刷新后是否需要重新读取模型取决于浏览器缓存，不能保证整站离线重开。细节见 `README_BROWSER_ASR.md`。

## 直接启动

先准备 Python 3.9 或更新版本。本机使用浏览器识别时，Python只负责提供网页文件，无需先安装Vosk。

1. 保持整个项目文件夹完整，包括 `browser-asr.js`、`vendor/`、`models-browser/` 和 `audio/`，双击 **`start_demo.cmd`**。
2. 它会检查 `http://127.0.0.1:8770`。已有正确的服务就复用；没有则在后台启动，再打开系统默认浏览器。
3. 在正常的 Edge、Chrome 或 Firefox 窗口里使用。不要用文件管理器预览、单文件 HTML 的 `file://` 地址或应用内嵌预览窗口来验证麦克风。
4. 点击“点击说话”，在浏览器弹出的提示中允许本机页面使用麦克风。
5. 先说“介绍一下宁波诺丁汉大学”，说完停顿或点击“结束并发送”。页面应显示识别文字，然后播放回答。

未安装Python原生识别器时，页面自动使用浏览器模型，这是正常状态。启动器会查找可用的Python运行时，优先使用项目虚拟环境，也会尝试电脑上其他可用运行时；找不到时会提示安装。它不会修改防火墙、自动授予麦克风权限或上传录音。

## 浏览器没有弹出麦克风提示

查看地址栏中的站点权限，将 `http://127.0.0.1:8770` 的麦克风权限设为允许，刷新后重试。如果系统本身禁用了麦克风，还需要在 Windows 设置中的隐私和麦克风访问设置检查权限。确认浏览器选中了实际麦克风，而不是没有输入的虚拟设备。

识别模型就绪不代表浏览器已经获得麦克风权限。先观察页面输入电平是否随说话变化，再判断识别是否成功。模型加载、权限或内存出现问题时，文字输入和快捷问题仍可使用。

## 检查服务

在浏览器打开 `http://127.0.0.1:8770/api/status`。其中 `asr_available`、`asr_languages` 只描述Python原生识别器；未安装时返回 `false` 或空列表，不代表浏览器识别不可用。浏览器模型的加载和就绪情况以页面设置中的语音识别状态为准。

也可在本目录终端运行：

```powershell
py -3 healthcheck.py
```

`ok: true` 表示本机服务正常。安装原生识别器后，可额外使用 `--recognition-test` 提交一秒程序生成的静音；它不测试浏览器模型，也不使用真实麦克风。`recognition_test.ok: true` 表示Python识别路径可用，`microphone_tested: false` 表示仍需在浏览器中测试硬件。未安装原生识别器时，不需要运行这项额外测试。

如果 8770 被其他应用占用，启动器会停止并说明，不会终止其他进程。可执行 `start_demo.cmd --port 8771`，并使用打印的新地址。

## 可选 安装 Python 原生识别器

只有希望由本机Python处理识别时，才执行本节。公开仓库不携带 `.asr-vendor` 或原生 `models/` 目录，不能假定依赖与模型已经安装。在完整项目目录内执行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install vosk==0.3.45
.venv\Scripts\python.exe setup_asr.py zh
.venv\Scripts\python.exe setup_asr.py en
```

最后一行仅在需要原生英文识别时执行。首次安装需要联网，完成后重新启动服务。默认模式下，页面优先使用已就绪的当前语言Python识别器，否则使用浏览器模型；也可在设置中选择浏览器识别。

不同电脑、不同系统的虚拟环境与二进制依赖不能直接互相复制。浏览器使用 `models-browser/` 中的压缩模型，Python使用 `models/` 中的解压目录，两者路径不能直接互换。Linux原生识别安装见 `README_ASR.md`。

## 文件与服务边界

GitHub Pages不会运行 `server.py`，也不会连接访客电脑上的Python识别器；网站通过WebAssembly在浏览器中完成真实语音识别。localhost页面若选择Python原生识别，音频只提交给同一台电脑的服务。

两种识别方式都只负责把语音转成文字。云端情感合成与音色复刻仍需单独配置，不能因为网页能识别语音就认为这些能力已经接通。

后台服务日志位于 `.local/server-8770.log`；日志不记录原始录音、提问文字或 API Key。再次双击启动器不会重复启动同一个服务。
